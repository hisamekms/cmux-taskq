# `needs_session`

衝突（4）と再検証の失敗（5。宣言外のパスを含む）は`defer_integration`でrunを`needs_session`にし、理由を`last_error`、詳細（衝突ファイル、Gitの出力の末尾、rebase後のheadなど）を`integration_deferred`イベントに書いて、lease行を消しスロットを空ける。worktreeは衝突なら検証済みhead、再検証の失敗ならrebase済みのheadに置いたまま残す。runはTaskを占有し続け、`ready`/`cancel`はできない。

`integrate`は呼ばれた時点で、runに`integration_approved`イベント（`status`: 呼ばれた時のrunのstatus、`pid`、`push`: `--no-push`でなければtrue）を1回だけ記録する。supervisorが承認済みのrunを着地させるときは、この`push`に従ってmainを`origin`へpushする（`integrate`と同じ`push_main`）。`integrate`を呼ぶことが着地の承認で（ADR-0016の決定5）、runtimeが自分で着地させるのは承認済みのrun、reviewがpassしたrun、`approve_landing`に`land`と答えたrun（`integration_approved`に`ask_id`を付けて記録する）だけ（[ADR-0027](../../adr/0027-keep-worker-session-through-review-revise-verdict-and-merge-tree-precheck.md)）。`integration_deferred`のpayloadには`resumes_left`（supervisorが残り何回resumeするか。3から数える試行（下の「試行の数え方」）の件数を引いた値で、0未満にならない）が付く。

**試行の数え方**（[ADR-0047](../../adr/0047-irregularities-in-three-layers-recovery-job-ask-reasons-and-goal-review.md)の決定24、task 358）: 判定はdomainの`domain::resume`がrunのイベントだけから行う。`resume_started`ごとに、それより前のイベントで (a) reviewがpass済み（`integration_approved`がある（`integrate`か`approve_landing`の`land`）か、最新の`review_finished`の`verdict`が`pass`）で、(b) runを`needs_session`にした最新のイベント（`integration_deferred` / `integration_error` / `evidence_missing` / `scope_violation` / `landing_decided` / `triage_finished` / `triage_decided`）が`code: rebase_conflict`の`integration_deferred`なら、その試行は**衝突だけの試行**で、上限の3回（`MAX_RESUME_ATTEMPTS`）に数えない（`ResumeCount::conflict_only`）。それ以外（検証の失敗、`evidence_missing`、`scope_violation`、人の`send_back`、triageのresume、reviewがpassしていない衝突）は数える（`ResumeCount::counted`）。衝突だけの試行は別に`CONFLICT_ONLY_RESUME_LIMIT`（5）で止める（同じ衝突が解けないまま回り続けないための柵。ADR-0047の`[resume].conflict_only_limit`の設定は未実装で、定数）。数える試行が3回か、衝突だけの試行が5回に達したrunは試行を使い切っている（`ResumeCount::exhausted`）。triageのresumeの上限、着地前の衝突の確認（precheck）が数える`resume_started`、`resumes_left`も、数える試行だけを見る。

supervisorは`needs_session`のrunを自分でresumeする（ADR-0019の決定1。`resume_parked_runs`）。ループの各回で、adoptの後、claimの前に、空きslotの数まで`needs_session`のrunを古い順に見る。試行を使い切ったrun（上の「試行の数え方」）、staleでないleaseを持つrun、前のsessionのwrapperのプロセスがまだ生きている（未終了でPIDが生きている。heartbeatが止まっていても）runは飛ばす。このsupervisorが見ていないsessionと同じworktreeで2つ目のsessionを始めないため。resumeの前に、このrunの`resume_finished`に記録された`workspace_id`のうち閉じていないもの（手放したsession、errorで残したもの）が`WorkspaceBackend::exists`でまだ開いていれば閉じる。workspaceはtitleで探さない（[ADR-0026](../../adr/0026-identify-workspaces-by-uuid-env-and-queue-group.md)）ので、人が手で開いたresume workspaceや、resume中に死んだsupervisorが開いたworkspace（IDの記録が無い）は見つけない。後者はwrapperが生きている間は上の条件で飛ばし、終わった後に残ったworkspaceは人が閉じる。

0. **解消済みの確認**（`resolved_head`、task 148）: resumeを始める前に、前の試行で解消済みかを確かめる。前の試行のsessionがreceiptを書き直した後に判定された（rebaseもreceiptも済んでいて、次の試行のsessionが何もせずにidleになる）runは、`rewritten_receipt`がresume開始より新しいreceiptを要求するので`unresolved`になり、試行を空費する（task 122）。次をすべて満たせばsessionを開かない: (a) runを`needs_session`にした最後のイベント（`integration_deferred` / `integration_error` / `evidence_missing` / `scope_violation` / `landing_decided`）が`landing_decided`（人の`send_back`。指摘への対応はsessionが要る）ではなく、それらと`resume_finished` / `resume_skipped`のうち最後が`outcome: unresolved`の`resume_finished`（parkの後にsessionの走ったresumeが終わっている。開けなかったresume（`outcome: error`）は何も変えていないので数えない）、(b) receiptがparseでき、`run_id`がこのrunで`succeeded`、taskの`required_evidence`を満たす、(c) receiptの`commit`がworktreeのHEADに一致し、worktreeがclean、(d) HEADが今の`main`ではなく、`main`を祖先に持つ（`merge-base --is-ancestor`）。どれかが読めない・満たさないときは従来どおり1に進む。宣言外のパス（`--paths`）はここでは見ず、skipの後の[Validation](validation.md#validation)か着地が検査する。満たせば`skip_resume`が1トランザクションで`begin_resume`と同じ確認（`needs_session`、leaseが無いかstale、heartbeatしている未終了のprocessが無い）をしてleaseし（`lease_acquired`の`reason: resume_skipped`。sessionを始めないので前のsessionの`run_processes`の行は消さない）、`resume_skipped`（`head`、`main`、`approved`、`status`）を記録する。`resume_started`は記録しないので試行回数は増えず、試行が3回に達したrunには行わない（最初の除外条件のまま）。`integration_approved`があればrunは`needs_session`のまま着地スロットを待ち、下の5と同じく`land_integrating`で着地させる。無ければrunを`validating`にし、sessionの無いまま[Validation](validation.md#validation)→[Review](review.md#review-supervisor)に進める。skipの後にどの経路で`needs_session`に戻っても（着地の`integration_deferred`、着地スロット待ちのerror、supervisorの死）、最後が`resume_skipped`かparkのイベントなので(a)が成り立たず、次は必ずsessionを開いてresumeする（skipはresumeを挟まずに繰り返さない）。未承認でskipしたrunを持つsupervisorが`validating`か`awaiting_integration`のうちに死んだときは、wrapperが無い（`begin_resume`が消した）か生きていなくても、最後のresumeのイベントが`resume_skipped`ならadoptする（`run_adopted`の`wrapper`はwrapperが無ければnull）。そのrunのsessionは無いものとして扱う（`session_of`）。`resume_skipped`はattentionにしない。
1. **開始**: `begin_resume`が1トランザクションで、runがまだ`needs_session`で試行を使い切っておらず、leaseが無いかstale（staleなら置き換える）で、heartbeatしている未終了のprocessが無いことを確かめ、runをこのsupervisorのtokenでleaseし（`lease_acquired`の`reason: resume`）、`supervisor_token`を移し、前のsessionの`run_processes`の行を消し（履歴はイベントに残る）、`resume_started`（`attempt`: 数えない試行も含めた通し番号、`counted`: この試行を上限に数えるか、`reason`、`main`）を記録する。`reason`は最後の`integration_deferred` / `integration_error` / `evidence_missing` / `scope_violation` / `landing_decided`の`reason`（無ければ`last_error`）。そのイベントが`scope_violation`か、`scope_violation`を持つ`integration_deferred`なら、下の3の依頼を宣言パス用の文面にする。そのイベントが`evidence_missing`か、`checks`を持つ`integration_deferred`（上の要求evidenceで着地しなかった）なら、下の3の依頼をevidence用の文面にする、`main`はその時点の`refs/heads/main`。runの状態は`needs_session`のままで、新しい状態は足さない。進行は`resume_started` / `resume_finished`で読む。
2. **起動**: workerと同じ経路で起動する。runtimeのsnapshot（`<run-dir>/runner`）をこのsupervisorのbinaryで置き換え（workerの時のbinaryは`--resume`を知らないことがある）、`runner --db … session --run <run-id> --lease <token> --claude <claude> --resume`を`WorkspaceBackend::create_resume`でworkerと同じtitle（`run_workspace_name`: `[<repo>]worker#<task-id> - <task title>`。[ADR-0028](../../adr/0028-workspace-titles-are-repo-and-role.md)。titleは表示専用）、description `run <run-id> resume`（`resume_workspace_description`）のworkspaceとしてworktreeで開く。workerと同じenvとgroup（`--env DAGQ_ROLE=worker` / `DAGQ_QUEUE`、queueのworkspace group。[ADR-0026](../../adr/0026-identify-workspaces-by-uuid-env-and-queue-group.md)）を付け、cmuxが返したUUIDで扱う。wrapperは`register_resume_wrapper`（`needs_session`でこのtokenのlease）で登録し、`AgentProvider::resume_command`でClaudeを起動する。Claude Codeでは`claude --resume <run-id> --debug-file <run-dir>/claude-resume.log --add-dir <run-dir> --settings <run-dir>/claude-settings.json`で、workerと同じ`Stop` hookのidle markerを使う（素の`claude --resume`で開くと出たLSP pluginのダイアログを避ける）。agentは`register_resume_agent`で登録し、runの状態は変えない（`wrapper_started`、`agent_started`は同じkindとpayloadで記録される）。wrapperが45秒以内に登録しなければresumeのerror。
3. **解消依頼**: agentが登録されたら画面（`capture`）を読み、Claude Codeの入力欄が準備できた（`AgentSignals::input_ready`。画面の下端から14行以内の最後の罫線と、その上の直近の罫線の間が入力欄で、その1行目が`❯` / `>` / `!`で始まり、ダイアログが無い。起動中のshellの行、welcomeの枠だけの画面、Claude Codeが終わって`Resume this session with:`の上に残った最後の枠は準備前）状態が`resume_prompt_delay`（既定5秒。固定の待ちは下限として残す）続いてから、定型の解消依頼を[送信と確認](session-send.md#sessionへの送信と確認)の経路（`WorkspaceBackend::send_text`。cmuxでは`cmux send`と、文面の長さに応じた待ち（`paste_settle`）の後のEnter。`cmux send`は`\n`などをキーとして読むので、改行とタブは空白、backslashは`/`にした1行で送る）で送る（task 285。2026-09-24のtask 221のrun f8f7c65dでは、agentの登録から6秒後の依頼がClaude CodeのREPLのmountより前に届いて消え、sessionは1時間のresume timeoutまで待った）。agentの登録から`registration_timeout`（既定45秒）経っても準備が見えなければ`input_not_ready`（`workspace_id`、`waited_secs`、`prompt`: ダイアログならその種類、無ければnull、`excerpt`）を記録し、inbox宛ての`answer_prompt`のaskを1回開く（`ask_unsubmitted`）。準備ができれば依頼はその後に送り、送る前にそのaskを`the input box got ready and the request was sent; closed by the runtime`で閉じる。登録から`resume_timeout`経っても送れなければ(iii)と同じく`/exit`を送る。ただしダイアログが出ていれば（`/exit`のEnterが選択肢を選ぶので）何も打たず、`exit_timeout`の後の`stuck_exit`のaskで手放す。送った後は、sessionが依頼を受け取った兆候を`StartCheck`が見る（[送信と確認](session-send.md#sessionへの送信と確認)の3）。同じ文面を`<run-dir>/resume-<attempt>.txt`に残す。内容は、`integrate`が`needs_session`を返したこと、`Reason:`（上の`reason`）、rebase先の`main`とrunのbase commit、base..mainに着地したtask（mainのcommitの`Dagq-Task` trailerを古い順に引き、taskのtitleと`integrated` runのreceiptの`summary`）、手順（`git rebase <main>`と衝突の解消、`verification_commands`の再実行とcommit、worktreeをcleanに保つ、自分が起動したbackgroundの処理をすべて止める（`STOP_BACKGROUND`）、receiptを新しいheadで一時ファイルとrenameで書き直す、変更が不要なら`result: failed`と理由、mergeもpushもしない、終わったら短く報告して止まり`/exit`は打たない）。理由が`evidence_missing`（または`checks`付きの`integration_deferred`）のrunでは、冒頭を「validationがreceiptの要求evidenceの欠落を見つけた」に、手順1–2を「reasonが名指す不足しているcheckを実行してreceiptにevidenceを書く。ファイルが変わればcommitして検証コマンドを再実行する」に変える。理由が`scope_violation`（または`scope_violation`付きの`integration_deferred`）のrunでは、冒頭を「run (task) changes paths outside the task's --paths (<globs>)」に、手順1–2を「reasonが名指すパスを`git merge-base HEAD <main>`の状態に戻し（そこに無かったものは消す）commitする。そのパスが無ければtaskができないなら`failed`のreceiptに必要なパスを書く。検証コマンドを再実行する」に変える。
4. **終了**: `integration_approved`の無いrunで(i)が成り立ったときは`/exit`を送らない。`resume_finished`（`outcome: resolved`、`status: validating`、`workspace_closed: false`、`session_live: true`）を記録してleaseを持ったままrunを`validating`にし、resumeしたsessionを開いたまま[Validation](validation.md#validation)→[Review](review.md#review-supervisor)に進む（[ADR-0027](../../adr/0027-keep-worker-session-through-review-revise-verdict-and-merge-tree-precheck.md)の決定3。`/exit`とcloseはverdictの後）。それ以外で`/exit`を1回だけ送る条件は3つ。(i) resume開始より新しいreceiptがparseでき、`run_id`がこのrunで、`succeeded`で`commit`がcleanなworktreeのHEADに一致し、taskの`required_evidence`を満たす（または`failed`）状態で、idle markerがreceiptより新しくなった。(ii) そういうreceiptが無いまま、idle markerが解消依頼を送った時刻より新しくなった（解消できずに応答を終えた、質問して止まった。実際のClaudeは自分では終わらない）。(iii) 依頼を送ってから`resume_timeout`（既定1時間）経ってもどちらにもならない（依頼が届かなかった、ダイアログで止まった、backgroundの処理が終わらない）。(i)(ii)のidleは[Receipt and session exit](receipt-and-session-exit.md#receipt-and-session-exit)の1の定義で、`running`のbackgroundの処理を示すmarkerはidleではない。`ResumeWatch::poll`はidle markerを先に読み、その後でworktreeのHEADとreceiptを読んでverdictを出す（task 141をtask 147に統合: verdictの後にmarkerを読むと、その間に書かれたreceiptとmarkerで、解消したsessionを(ii)の「解消せずにidle」と取り違えた）。wrapperが終了したら画面を`<run-dir>/terminal-resume-<attempt>.txt`に保存し、workspaceを閉じ（失敗はsupervisor logに書き`workspace_closed: false`）、`finish_resume`で`resume_finished`（`attempt`、`outcome`、`head`（worktreeのHEAD）、`workspace_id`、`workspace_closed`、`approved`、`status`: resume後のrunのstatus、未解消なら`exhausted`）を記録する。`outcome`は`resolved`（(i)のreceipt）、`failed`（receiptが`failed`）、`unresolved`（新しいreceiptが無い・別のrunのもの・HEADと一致しない・worktreeがcleanでない・要求evidenceがまだ欠けている）。`/exit`から`exit_timeout`（120秒）経ってもwrapperが終わらなければ、`/exit`は再送せず、sessionを手放す: `outcome: unresolved`、`exit_timed_out: true`、`workspace_closed: false`でleaseを外し、workspaceは残す（slotとleaseと`down --wait`のdrainを永久に止めないため）。そのsessionが生きている間はそのrunを次の試行に回さない（attentionは`resuming (runtime)`のまま）。確認画面は放置しても消えないので、手放す前にworkerのsessionと同じ`stuck_exit`のaskを`ask_stuck_exit`で開く（task 147。同じ（run、kind）のopenなaskがあれば作らない。questionの「その後」は、試行が残っていれば「`needs_session`のまま、sessionが終われば再びresumeする」、最後の試行なら「人に返る」（6の`decide`のask）。askの作成に失敗してもlogに書くだけでverdictは変えない）。askは、`resume_parked_runs`がそのrunのwrapperが生きていない（未登録・終了済み・pidが死んでいる）のを見た回に`close_stuck_exit_asks`で閉じる（slotの空きに関わらず`needs_session`のrunを見るたび、試行を使い切ったrunも含めて。残したworkspaceを閉じるのは次の試行を始めるときだけなので、試行を使い切ったrunのworkspaceは残る）。
5. **その後**: `resolved`で`integration_approved`があれば（0の解消済みの確認で`resume_skipped`になった承認済みのrunも）、`landing_queued`（`via: resume`）を記録し、leaseを持ったまま着地スロットが空くのを待ち（他のrunが`integrating`なら次の回に回す）、`begin_integration`（同じtokenのleaseはそのまま使う）から`integrate`と同じ関数（`land_integrating`: rebase、再検証、squash、完了、後始末）を別threadで走らせる。着地がまた`needs_session`になればleaseは外れ、次の回に1に戻る。`integration_approved`が無ければ、上の4のとおりsessionを開いたままrunを`validating`にしてreviewに進む（resumeしたsessionが自分で終わっていた場合も同じ経路で、workspaceはreviewの後に閉じる）。`failed`ならrunを`failed`にし、`last_error`を`session reported the run as failed: <summary>`にする。`unresolved`は`needs_session`のままleaseを外し、試行が残っていれば次の回に再びresumeする。
6. **打ち切りとerror**: 試行を使い切った後の`resume_finished`が未解消なら`exhausted: true`になる。次の`resume_parked_runs`で、そのrunにstaleでないleaseも生きているwrapperも無ければ（slotの空きに関わらず）、supervisorは次の**引き継ぐretry**か、人に渡すかを決める。

   **引き継ぐretry**（ADR-0047の決定24、task 358）: runが今も衝突だけで`needs_session`（上の(a)(b)がすべてのイベントについて成り立つ）で、同じtaskのどのrunにも`action: retry_inherit`の`triage_finished`が無ければ（taskごとに1回まで。`inherits_on_exhaustion`）、人に聞かずにretryする。runの`result_commit`（reviewがpassした検証済みのcommit。無ければ、rebaseの途中でないworktreeのHEAD）がbaseと違えば、それを`refs/dagq/runs/<run-id>`に向け（branchを消されても残るように）、`exhaust_resumes`（store）が1トランザクションで下と同じ確認と、衝突だけで止まっていることとtaskごとに1回までであることの再確認をしてrunを`failed`にし、taskを`in_progress`から`ready`に戻し（中身は変えないのでplan reviewにはかけない。triageの`retry`と同じ例外）、`auto_repaired`（`layer: runtime`、`repair: inherit_retry`、`conditions`: `review: pass`、`parked: rebase_conflict`、試行の数、`branch`、`head`）と`triage_finished`（`by: runtime`、`code: resume_exhausted`、`verdict` / `action: retry_inherit`、`inherit`: `branch`と`head`、`resumes`、`counted_resumes`、`conflict_only_resumes`）を記録する。askは開かない。残したworkspaceはtriageと同じく閉じ、worktreeとbranchはtaskが`ready`なので残る。次のrunのclaimでsupervisorは、前のrunのうち最も新しい`retry_inherit`で終わったrunがあれば（`retried_with_inheritance`。直前のrunが早くに失敗してtriageでretryされても引き継ぐ）、worker promptに引き継ぎの節（`Carried over from run <id>`: 前のrunのreviewはpassしたが衝突で試行を使い切ったこと、commit（`refs/dagq/runs/<id>`とbranch）と、そのrun自身のcommitの範囲（headと新しいrunのbaseのmerge-baseから。途中までrebaseしたresumeがmainのcommitを下に積んでいても、それを含めない）、`git cherry-pick <merge-base>..<head>`などで今のmain（新しいrunのbase）に載せ直して衝突を解き、検証を再実行して自分のheadでreceiptを書くこと、前のreceiptのpathとsummary）を足し、新しいrunに`run_inherited`（`inherit_from_run`、`head`、`branch`）を記録する。commitがbaseと同じ（載せ直すものが無い）か、refを作れなければ人に渡す。2回目の使い切りも人に渡す（ADR-0047は復旧jobに回すとするが、`resume_exhausted`の復旧jobは未実装）。

   **人に渡す**（`exhaust_resumes`。ADR-0044の決定3、task 71の「attentionで人に返す」の乗せ替え）: headlessのtriageは起動せず、先にtriageと同じ`decide`のask（`asked_by: supervisor`、optionsは`retry` / `cancel`。resumeはもう選べない。questionにresumeの回数、`last_error`、run dir）をinbox宛てに開き、`exhaust_resumes`（store）が1トランザクションで、runがまだ`needs_session`で試行を使い切り、taskが`in_progress`でrunがその最新で、staleでないleaseが無いことを確かめ、runを`failed`にし（`last_error`は`resumed N times (at most 3) and still needs a session: <元のlast_error>`。衝突だけの試行があれば括弧の中に数える試行と衝突だけの試行の内訳を書く）、`triage_finished`（`by: runtime`、`verdict` / `action: ask`、`ask_id`、`reason`、`resumes`（すべての試行）、`counted_resumes`、`conflict_only_resumes`、`previous_status: needs_session`、`status: failed`）を記録する。`triage_finished`があるので、triageはこのrunを再びtriageしない。続けてtriageと同じ`close_triaged_workspaces`で残したworkspaceを閉じる。answerはtriageの`decide`と同じ`apply_triage_answers`が適用する（`retry`はtaskを`ready`、`cancel`はtaskをcancel。askのoptionsに無い答え、たとえば`resume`は適用せずinboxが読む）。askを開いた後でstoreの遷移がrunの変化で成り立たなければ、そのpassが開いたaskは取り下げて（`withdrawn: …`と答えて）閉じる。workspaceの作成・送信・heartbeat切れなどresume自体のerrorは`resume_finished`（`outcome: error`、`error`、`exhausted`）とsupervisor logに書き、leaseを外す。runの`last_error`（衝突の理由）は変えず、試行は1回と数える。resume workspaceは、leaseを外した時点でwrapperが未登録（leaseが無いのでもう登録できない）か終了済みなら閉じ（作成の途中で失敗してIDが返らなければ何もしない）、wrapperが生きていれば調査のため残す（`resume_finished`の`workspace_id`に記録する）。残したworkspaceは上の条件で次の試行を止めるが、このrunの`resume_finished`に記録されたworkspaceは、runのwrapperがもう生きていなければ次の回に閉じて次の試行を始める。着地スロットを待つ間（`AwaitingSlot`）のerrorでは`resume_finished`は記録済みなので、leaseだけを外す。resume中にsupervisorが死んだ場合、leaseはstaleになる。runの状態は`needs_session`のままでadoptの対象ではなく、`integrate`はleaseがあるので拒否される。前のsessionが終われば（人が画面を見て`/exit`を送る）、次のsupervisorがstaleなleaseを置き換えて（`lease_acquired`の`previous_token`）次の試行を始める。

resume workspaceを作るのはsupervisorだけ。`status`のattentionは、`needs_session`のrunならどの場合も`next: resuming (runtime)`（resume中、試行が残っている、生きているsessionが次の試行を止めている、resume中のsupervisorが死んだ、試行を使い切って`decide`のaskへ移る直前のいずれもsupervisorのもの）。`kind`はrunを`needs_session`にした最新のイベント（payloadの`status`が`needs_session`のもの）。

セッションが変更不要と判断した場合はreceiptを`result: failed`と理由（`summary`）で書き直す。`integrate ID`は`fail_integration`でrunを`failed`にし（`integration_failed`。payloadの`receipt`にそのreceiptのJSON全体を持つ。`integration_receipt`は記録しない）、mainには触れない。worktreeは残る。`failed`になったrunはsupervisorがtriageする（[Triage](triage.md#triage-supervisor)。triageのresumeは`needs_session`に戻し、ここの試行の上限を通算で共有する）。
