# Reviewing the observer's output with the user

The observer is a headless job the supervisor starts every `--observe-interval` seconds (default 3600; 0 disables it) and once a day for the last 24 hours (`--observe-daily`). It reads `stats`, the latest notes, the open asks and the graph, and writes only three things. It never changes a run, task or goal; the queue refuses that from `DAGQ_ROLE=observer`. Run it by hand with `"$DAGQ" observe [--since CURSOR] [--daily]`, or print its prompt with `--dry-run`.

1. **See what it wrote.** `"$DAGQ" events --all` shows `observe_finished` with `notes`, `asks`, `goals`, `outcome` and `cursor`; its directory (`dir`) under `<queue dir>/observer/` holds `prompt.md`, `input.json` and `output.log`. An `outcome` other than `succeeded` left the cursor unchanged, so the next run reads the same window.
2. **Read the notes.** `"$DAGQ" notes [--goal ID] [--task ID]` lists them oldest first; `payload.by` is `observer` and `payload.kind` the slug it chose (`stall`, `failure`, `wait`, `capacity`, …). Walk the user through the ones that repeat. A note is a record, not a request: nothing waits on it.
3. **Decide each draft goal.** `"$DAGQ" goal list` shows `status: draft`; `"$DAGQ" goal show ID --full` has the proposal, its draft tasks and the observation ids it cites as evidence. Check the cited notes with the user, then either adopt it (edit the goal or its tasks first if needed, `lint`, then `submit --goal ID`: plan review makes the tasks `ready` and lifts the goal's draft on `pass`) or reject it (`goal close ID --verdict abandoned`). Do not adopt a draft without the user.
4. **Blocked asks are the inbox's.** The observer raises a threshold crossing from `stats.alerts` as `ask --kind blocked`, on the task or run, or on nothing for `idle_slots` and `backend_failures`. They show in `status --role inbox` and `asks --open`; the person picks one of its options there. When the answer is a new goal, register it here.
